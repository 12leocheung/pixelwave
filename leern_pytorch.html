Chapter 01

What is PyTorch?

PyTorch is an open-source machine learning library developed by Meta AI. It's the dominant tool for research and production deep learning, used to build everything from simple classifiers to the largest language models in the world.

Think of PyTorch like a very powerful scientific calculator — but instead of working on single numbers, it works on entire tables (grids) of numbers at once, and it can automatically figure out how to improve itself when it makes mistakes.

— Why PyTorch matters

Two ideas sit at the heart of PyTorch:

  1. Tensors — a generalised array that can live on a CPU or GPU and supports hardware-accelerated maths.
  2. Autograd — an automatic differentiation engine that computes gradients for you during backpropagation.

Installing PyTorch

Install with pip. The CPU-only version is fine for learning; add a CUDA suffix for GPU support.

Shell — Installation
pip install torch torchvision
pip install fetches PyTorch from PyPI. torch is the core library. torchvision adds image utilities and pre-trained vision models.
pip install torch --index-url https://download.pytorch.org/whl/cu121
CUDA 12.1 version — use this if you have an NVIDIA GPU. Replace cu121 with your CUDA version (check with nvidia-smi).

Your first import

Python — Imports
import torch
Import the main torch module. This gives you tensors, autograd, and all the core maths operations. Almost every PyTorch file starts with this.
import torch.nn as nn
Import the neural network module and alias it as nn. This contains all the building blocks: layers, activation functions, loss functions. The alias keeps code concise.
import torch.optim as optim
Import the optimiser module. Optimisers are algorithms that update the network's weights during training (e.g. SGD, Adam). Aliased as optim by convention.
import torch.nn.functional as F
Import functional operations. These are stateless versions of things in nn (like activation functions) that don't have learnable parameters. Very commonly aliased as F.
Convention

The aliases nn, optim, and F are universal conventions in the PyTorch community. You'll see them in virtually every tutorial, paper code release, and production codebase. Always use them.

import torch

import torch.optim as optim
import torch.nn.functional as F

print(torch.__version__)          # e.g. "2.3.0"
print(torch.cuda.is_available())  # True if GPU is available
Chapter 02

Tensors — The Foundation

A tensor is the fundamental data structure in PyTorch. It's a multi-dimensional array — like a NumPy array, but with built-in GPU support and gradient tracking.

Dimensions Name Real-world Example Shape
0DScalarA single loss value[]
1DVectorA single training example's features[784]
2DMatrixA batch of examples[32, 784]
3DTensorA sequence of word embeddings[8, 128, 512]
4DTensorA batch of colour images[16, 3, 224, 224]

Creating Tensors

Python — Creating Tensors
x = torch.tensor([1.0, 2.0, 3.0])
Create a 1D tensor from a Python list. The values are converted to float32 by default. This is the most direct way to make a tensor from data you already have.
x = torch.zeros(3, 4)
Create a 3×4 tensor filled with zeros. Useful as a blank slate, or to initialise output buffers. The arguments are the shape: 3 rows, 4 columns.
x = torch.ones(2, 3)
Create a 2×3 tensor filled with ones. Handy for masks or bias initialisations.
x = torch.randn(5, 5)
Create a 5×5 tensor of random values sampled from a standard Normal distribution (mean=0, std=1). This is the typical way to randomly initialise model weights.
x = torch.arange(0, 10)
Create a 1D tensor [0, 1, 2, …, 9]. Like Python's range() but returns a tensor. Useful for position indices in transformers.

Tensor Operations

Python — Shape & Operations
x.shape # or x.size()
Returns the shape of the tensor as a torch.Size object. For a batch of 32 images of 28×28 pixels: torch.Size([32, 28, 28]). This is the most important thing to check when debugging.
x.dtype
Returns the data type. Common types: torch.float32 (default for neural nets), torch.int64 (class labels), torch.bool (masks).
y = x.reshape(4, -1)
Reshape without changing data. The -1 means "infer this dimension". If x has 20 elements and you reshape to (4, -1), PyTorch works out -1 = 5. Crucial for feeding images into linear layers.
z = x + y
Element-wise addition. Standard Python operators work element-wise on tensors of the same shape. Same for -, *, /.
z = x @ y
Matrix multiplication. The @ operator is shorthand for torch.matmul(x, y). This is the most common operation inside neural network layers.
z = x.mean() z = x.sum(dim=1)
Reduction operations. Without dim, they reduce the entire tensor to a scalar. With dim=1, they reduce along dimension 1 (columns) and return a 1D result.
x = x.unsqueeze(0)
Add a dimension of size 1 at position 0. Turns shape [28, 28] into [1, 28, 28]. Used to add a batch dimension when processing a single example.
x = x.squeeze(0)
Remove a dimension of size 1 at position 0. The inverse of unsqueeze. Turns [1, 28, 28] back to [28, 28].

Broadcasting

When two tensors have different shapes, PyTorch tries to broadcast them — stretching smaller dimensions to match larger ones. This is powerful but can cause subtle bugs if you're not careful about shapes.

Python — Broadcasting
x = torch.ones(3, 4) y = torch.ones(4) z = x + y # shape: [3, 4]
y is broadcast across rows of x. The shape [4] is treated as [1, 4] and then "stretched" to [3, 4]. This lets you add a bias vector to every row of a matrix without a loop.
Shape Debugging Tip

The number one cause of bugs in PyTorch is mismatched tensor shapes. Get in the habit of printing x.shape at every step when writing new code. Many experienced practitioners do this religiously.

Complete Code tensors.py 
import torch

# --- Creating tensors ---
a = torch.tensor([1.0, 2.0, 3.0])       # From list
b = torch.zeros(3, 4)                    # 3x4 zeros
c = torch.randn(5, 5)                   # 5x5 random normal
d = torch.arange(0, 10)                 # [0, 1, 2, ..., 9]

# --- Inspecting ---
print(c.shape)    # torch.Size([5, 5])
print(c.dtype)    # torch.float32

# --- Operations ---
e = c + c                   # Element-wise add
f = c @ c                   # Matrix multiply
g = c.mean()               # Scalar mean
h = c.sum(dim=1)           # Sum each row → shape [5]

# --- Reshaping ---
flat = c.reshape(25)        # Flatten to 1D [25]
back = flat.reshape(5, -1) # Back to [5, 5]

# --- Broadcasting ---
row_bias = torch.ones(5)
biased = c + row_bias       # row_bias broadcast to [5, 5]
Chapter 03

Autograd — Automatic Differentiation

Training a neural network requires computing gradients — the derivatives of the loss with respect to every parameter. Autograd does this automatically by recording every operation on tensors that have requires_grad=True.

Imagine you're baking a cake and it comes out too salty. Autograd tells you, precisely, how much each ingredient contributed to the saltiness, so you know exactly what to change. Neural network training does the same thing with numbers.

— Why autograd matters
∂L / ∂w
The gradient: how much the loss L changes when we nudge weight w. We want this to be small (or zero) once trained.

How Autograd Works

Python — Autograd Walkthrough
x = torch.tensor(3.0, requires_grad=True)
Create a tensor and tell PyTorch to track operations on it. Setting requires_grad=True enables gradient computation. Model parameters always have this set automatically.
y = x ** 2
Perform an operation. PyTorch silently records this operation in a computation graph — it remembers that y was created by squaring x, so it knows how to differentiate it later.
y.backward()
Compute gradients by backpropagating. This walks backwards through the computation graph, applying the chain rule. After this call, gradients are stored in each tensor's .grad attribute.
print(x.grad) # tensor(6.)
Read the gradient. dy/dx = 2x = 2×3 = 6. That's the gradient: how much y changes per unit change in x, evaluated at x=3. The network uses this to decide how to update weights.

Controlling Gradient Tracking

Python — Gradient Context Managers
with torch.no_grad(): output = model(x)
Disable gradient tracking inside this block. Used during inference (making predictions) and evaluation. Speeds up computation significantly and reduces memory usage since no graph is built.
optimizer.zero_grad()
Clear accumulated gradients before each training step. Gradients accumulate (add up) by default in PyTorch. If you forget this, gradients from the previous batch will corrupt the current batch's update.
loss.backward()
Compute all gradients via backpropagation. Starting from the scalar loss value, this applies the chain rule backwards through every operation in the network to fill in .grad on all parameters.
optimizer.step()
Update parameters using the computed gradients. The optimiser reads .grad on every parameter and adjusts the parameter values in the direction that reduces the loss.
The Four-Step Training Rhythm

Every training step in PyTorch follows the same four beats: (1) zero_grad → (2) forward pass → (3) backward() → (4) step(). This rhythm is sacred. Deviate and your model won't learn.

Complete Code autograd_demo.py 
import torch

# Create a weight tensor that we want to learn
w = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(0.5, requires_grad=True)

# A simple forward pass: y = w * x + b
x = torch.tensor(3.0)
y_pred = w * x + b

# Compute loss (how wrong we are)
y_true = torch.tensor(10.0)
loss = (y_pred - y_true) ** 2

# Backprop: compute gradients
loss.backward()

# Inspect gradients — tells us how to change w and b
print(w.grad)   # d(loss)/d(w)
print(b.grad)   # d(loss)/d(b)

# Manually update weights (learning rate = 0.01)
with torch.no_grad():
    w -= 0.01 * w.grad
    b -= 0.01 * b.grad

# Always clear grads before next step!
w.grad.zero_()
b.grad.zero_()
Chapter 04

Linear Layers

A linear layer (also called a fully connected or dense layer) is the most fundamental building block of a neural network. It applies a linear transformation to the input: output = input @ weight.T + bias.

y = xWᵀ + b
x = input vector, W = learned weight matrix, b = learned bias vector, y = output vector

The layer has learnable parameters: the weights W and biases b. Training adjusts these to minimise the loss.

nn.Linear

Python — Linear Layer
layer = nn.Linear(10, 5)
Create a linear layer that takes a vector of size 10 as input and produces a vector of size 5. Internally this creates a weight matrix of shape [5, 10] and a bias vector of shape [5], both randomly initialised.
layer = nn.Linear(10, 5, bias=False)
Linear layer without a bias term. Sometimes you want no bias — for example when batch normalisation (covered later) makes it redundant. Set bias=False to exclude it.
x = torch.randn(32, 10) y = layer(x)
Pass a batch through the layer. x has shape [32, 10] — a batch of 32 examples, each with 10 features. y will have shape [32, 5]. The layer processes all 32 in parallel.
print(layer.weight.shape) # torch.Size([5, 10]) print(layer.bias.shape) # torch.Size([5])
Inspect the layer's parameters. layer.weight is the weight matrix and layer.bias is the bias vector. Both have requires_grad=True automatically — the optimiser will update them during training.
Why "Fully Connected"?

Every input neuron connects to every output neuron through its own weight. A layer with 784 inputs and 128 outputs has 784 × 128 = 100,352 weight connections — plus 128 biases. That's a lot of parameters, which is one reason we use other layer types (CNNs, attention) when structure in the data can be exploited.

Complete Code linear_layer.py 
import torch
import torch.nn as nn

# Create a linear layer: 784 inputs → 128 outputs
layer = nn.Linear(784, 128)

# Inspect the learnable parameters
print(layer.weight.shape)   # [128, 784]
print(layer.bias.shape)     # [128]

# Create a fake batch of 32 images, each flattened to 784 pixels
x = torch.randn(32, 784)

# Forward pass through the layer
y = layer(x)
print(y.shape)   # [32, 128] — 32 examples, 128 outputs each

# Count parameters
num_params = sum(p.numel() for p in layer.parameters())
print(f"Parameters: {num_params}")  # 784*128 + 128 = 100,480
Chapter 05

nn.Module — Building Blocks

Every neural network in PyTorch inherits from nn.Module. This base class provides parameter tracking, saving/loading, and device management for free. You define the architecture in __init__ and the forward computation in forward.

Defining a Network

Python — Custom Module
class MyNet(nn.Module):
Define a class that inherits from nn.Module. All PyTorch models are subclasses of this. The class name is yours to choose — by convention it's something descriptive like Classifier, MLP, or GPT.
def __init__(self):
The constructor. Called when you create an instance. You define all the layers with learnable parameters here. PyTorch automatically registers any nn.Module attribute as a sub-module, so its parameters are included when you call model.parameters().
super().__init__()
Always call the parent constructor first. This initialises nn.Module's internal bookkeeping. Forgetting this causes mysterious errors. It must be the very first line in __init__.
self.fc1 = nn.Linear(784, 256)
Define the first fully connected layer as an attribute. The name fc1 is your choice (fc = fully connected). PyTorch sees this is an nn.Module and automatically registers its parameters.
self.fc2 = nn.Linear(256, 10)
Define the output layer. 256 inputs (matching fc1's outputs), 10 outputs (one per class for a 10-class problem like MNIST). This is the prediction head.
def forward(self, x):
Define the forward pass. This is called when you do model(x). It describes how data flows through your layers. PyTorch's autograd records every operation here to enable backpropagation later.
x = F.relu(self.fc1(x))
Pass through layer 1, then apply ReLU. self.fc1(x) calls the linear layer's forward. F.relu applies the activation function (covered next chapter). The result becomes the new x.
x = self.fc2(x) return x
Pass through the output layer and return. No activation function here — the loss function (CrossEntropy) expects raw logits. These are the raw un-normalised predictions, one per class.

Using nn.Sequential

For simple networks where data flows straight through layers without branching, nn.Sequential is a shortcut — no need to write a class:

Python — Sequential
model = nn.Sequential( nn.Linear(784, 256), nn.ReLU(), nn.Linear(256, 10) )
Chain layers in order. Data is passed through each layer in sequence: linear → ReLU → linear. nn.Sequential creates a module that automatically chains the forward calls. Great for prototyping; use a custom class for anything complex.
Complete Code nn_module.py 
import torch
import torch.nn as nn
import torch.nn.functional as F

# Method 1: Custom class (preferred for non-trivial networks)
class MLP(nn.Module):
    def __init__(self, input_dim, hidden_dim, output_dim):
        super().__init__()
        self.fc1 = nn.Linear(input_dim, hidden_dim)
        self.fc2 = nn.Linear(hidden_dim, hidden_dim)
        self.fc3 = nn.Linear(hidden_dim, output_dim)

    def forward(self, x):
        x = F.relu(self.fc1(x))
        x = F.relu(self.fc2(x))
        x = self.fc3(x)
        return x

# Instantiate
model = MLP(784, 256, 10)

# Inspect parameters
total = sum(p.numel() for p in model.parameters())
print(f"Total parameters: {total:,}")

# Forward pass
x = torch.randn(32, 784)
logits = model(x)           # Calls model.forward(x)
print(logits.shape)          # [32, 10]

# Method 2: Sequential (simple architectures)
model2 = nn.Sequential(
    nn.Linear(784, 256),
    nn.ReLU(),
    nn.Linear(256, 10)
)
Chapter 06

Activation Functions

Without activation functions, stacking linear layers is mathematically equivalent to a single linear layer — you'd never learn complex patterns. Activation functions introduce non-linearity, allowing networks to approximate any function.

ActivationFormulaUse CaseNotes
ReLUmax(0, x)Hidden layers — general purposeFast, simple. Can "die" (output always 0)
GELUx · Φ(x)Transformers, BERT, GPTSmoother than ReLU; state of the art
Sigmoid1/(1+e⁻ˣ)Binary classification outputSquashes to [0, 1]. Suffers vanishing gradients in deep nets
Tanh(eˣ - e⁻ˣ)/(eˣ + e⁻ˣ)RNNs, some hidden layersSquashes to [-1, 1]. Zero-centred, better than sigmoid
Softmaxeˣᵢ / ΣeˣⱼMulti-class outputConverts logits to probabilities that sum to 1
LeakyReLUmax(αx, x)When ReLU dies are a problemAllows small negative gradients

Using Activations

Python — Activation Functions
x = F.relu(x)
ReLU via functional API. Replaces all negative values with 0. Fast and effective. The default choice for hidden layers in most networks. Use this unless you have a reason to choose otherwise.
x = F.gelu(x)
GELU (Gaussian Error Linear Unit). Used in GPT, BERT, and most modern transformers. It's a smoother, probabilistic version of ReLU. Slightly more computationally expensive but consistently better in practice for language tasks.
probs = F.softmax(logits, dim=-1)
Softmax to get probabilities. Takes raw logit scores (any real numbers) and converts them to a probability distribution (all values between 0 and 1, summing to 1). dim=-1 applies it to the last dimension (the class scores). Note: nn.CrossEntropyLoss applies softmax internally, so don't double-apply.
prob = torch.sigmoid(x)
Sigmoid for binary output. Squashes a single score to a value between 0 and 1 (a probability). Used in the final layer for binary classification (yes/no tasks).
# As a layer (in nn.Sequential) nn.ReLU() nn.GELU() nn.Sigmoid()
Module versions. These are identical to the functional versions but can be added to nn.Sequential or used as class attributes. They have no learnable parameters.
Quick Rule of Thumb

Use ReLU for simple/quick experiments. Use GELU for transformer architectures. Use Sigmoid only on the final output of a binary classifier. Use Softmax when you need interpretable probabilities — but remember CrossEntropyLoss does it for you during training.

Complete Code activations.py 
import torch
import torch.nn as nn
import torch.nn.functional as F

x = torch.tensor([-2.0, -1.0, 0.0, 1.0, 2.0])

# ReLU: negative → 0, positive unchanged
print(F.relu(x))       # [0, 0, 0, 1, 2]

# GELU: smooth near-zero, similar to ReLU for large pos
print(F.gelu(x))

# Sigmoid: everything squashed to (0, 1)
print(torch.sigmoid(x))  # [0.12, 0.27, 0.5, 0.73, 0.88]

# Softmax on logits (e.g. 3-class prediction scores)
logits = torch.tensor([2.0, 1.0, 0.5])
probs = F.softmax(logits, dim=0)
print(probs)          # sums to 1.0
print(probs.sum())    # tensor(1.0)

# In a Sequential model
model = nn.Sequential(
    nn.Linear(64, 128),
    nn.GELU(),           # Non-linearity after each linear layer
    nn.Linear(128, 10)
)
Chapter 07

Loss Functions

A loss function (or criterion) measures how wrong your model's predictions are. It outputs a single scalar number — the loss. The entire goal of training is to minimise this number.

Python — Loss Functions
criterion = nn.CrossEntropyLoss()
Cross-Entropy Loss for multi-class classification. Expects raw logits (not softmax probabilities) and integer class labels. Internally applies log-softmax then negative log-likelihood. The standard choice for classification tasks like image recognition or next-token prediction.
loss = criterion(logits, labels)
Compute the loss. logits has shape [batch, num_classes], labels has shape [batch] with integer class indices. Returns a scalar tensor. Low loss = model predicts correctly; high loss = it's wrong.
criterion = nn.MSELoss()
Mean Squared Error for regression. Measures the average squared difference between predictions and targets. Use this when the output is a continuous value (e.g. predicting house prices, temperatures, or embeddings).
criterion = nn.BCEWithLogitsLoss()
Binary Cross-Entropy for binary classification. The safe version — it applies sigmoid internally, which is numerically more stable than applying sigmoid then BCE manually. Use when predicting yes/no outcomes.
Complete Code loss_functions.py 
import torch
import torch.nn as nn

# --- Multi-class classification (e.g. MNIST: 10 classes) ---
logits = torch.randn(4, 10)          # 4 examples, 10 class scores
labels = torch.tensor([3, 7, 1, 9])  # True class indices

criterion = nn.CrossEntropyLoss()
loss = criterion(logits, labels)
print(f"CE Loss: {loss.item():.4f}")

# --- Regression (predicting a number) ---
predictions = torch.randn(8, 1)
targets = torch.randn(8, 1)

mse = nn.MSELoss()
loss_r = mse(predictions, targets)
print(f"MSE Loss: {loss_r.item():.4f}")

# --- Binary classification (e.g. spam / not spam) ---
logits_binary = torch.randn(8, 1)
labels_binary = torch.randint(0, 2, (8, 1)).float()

bce = nn.BCEWithLogitsLoss()
loss_b = bce(logits_binary, labels_binary)
print(f"BCE Loss: {loss_b.item():.4f}")
Chapter 08

Optimisers

An optimiser uses the gradients computed by backward() to update the network's parameters in a direction that reduces the loss. Different optimisers have different strategies for doing this.

Python — Optimisers
opt = optim.SGD( model.parameters(), lr=0.01 )
Stochastic Gradient Descent. The simplest optimiser: param = param - lr × grad. model.parameters() passes all learnable tensors to the optimiser. lr (learning rate) controls the step size. Good for learning fundamentals; Adam is usually faster in practice.
opt = optim.Adam( model.parameters(), lr=3e-4 )
Adam — the default for most deep learning. Combines momentum (remembers recent gradient directions) with adaptive learning rates per parameter. Converges faster than plain SGD in most cases. 3e-4 is the "Karpathy constant" — a reliable default learning rate for Adam.
opt = optim.AdamW( model.parameters(), lr=3e-4, weight_decay=0.01 )
AdamW — the standard for training LLMs. A corrected version of Adam that handles weight decay (a regularisation technique that prevents weights from growing too large) properly. The go-to choice for transformers. GPT-2, GPT-3, and most modern LLMs trained with AdamW.
scheduler = optim.lr_scheduler.CosineAnnealingLR( opt, T_max=100 )
Learning rate scheduler. Gradually reduces the learning rate over training. Cosine annealing is popular — it starts high and smoothly decays following a cosine curve. Call scheduler.step() after each epoch.
Complete Code optimisers.py 
import torch
import torch.nn as nn
import torch.optim as optim

model = nn.Linear(10, 1)

# Adam with a learning rate of 3e-4
optimizer = optim.Adam(model.parameters(), lr=3e-4)

# AdamW — prefer this for transformers
optimizer = optim.AdamW(
    model.parameters(),
    lr=3e-4,
    betas=(0.9, 0.999),   # momentum coefficients (defaults)
    weight_decay=0.01
)

# Cosine annealing scheduler
scheduler = optim.lr_scheduler.CosineAnnealingLR(
    optimizer, T_max=100
)

# One optimisation step (inside training loop)
x = torch.randn(4, 10)
target = torch.randn(4, 1)

optimizer.zero_grad()            # Clear old gradients
output = model(x)                 # Forward pass
loss = nn.MSELoss()(output, target) # Compute loss
loss.backward()                  # Backprop
optimizer.step()                 # Update weights
scheduler.step()                 # Decay learning rate
Chapter 09

The Training Loop

The training loop is the engine of learning. It repeatedly feeds batches of data through the network, measures the error, computes gradients, and updates the weights until the model is good enough.

Python — Training Loop Line by Line
for epoch in range(num_epochs):
Outer loop over epochs. One epoch = one full pass through the entire training dataset. Typical training runs from 10 to hundreds of epochs depending on dataset size and task complexity.
model.train()
Put the model in training mode. This enables layers that behave differently during training vs. evaluation — specifically Dropout (randomly zeros activations) and BatchNorm (uses batch statistics). Essential to call before your training loop.
for X, y in train_loader:
Inner loop over mini-batches. train_loader is a DataLoader that yields batches. X is the batch of inputs, y is the batch of labels. Each iteration processes one mini-batch (e.g. 32 examples at a time).
optimizer.zero_grad()
Clear gradients from the previous batch. Critical step — PyTorch accumulates (adds) gradients by default, so if you forget this, gradients from the previous step will still be there, corrupting the current update.
logits = model(X)
Forward pass. Run the input batch through the network. The result, logits, contains the model's raw predictions — one vector of class scores per example in the batch.
loss = criterion(logits, y)
Compute the loss. Compare predictions to ground-truth labels. This scalar tells us how wrong the model is on this batch. This is what we want to drive to zero.
loss.backward()
Backpropagation. Computes the gradient of the loss with respect to every parameter in the network. After this call, every parameter's .grad attribute holds the direction we should nudge it to reduce the loss.
optimizer.step()
Update weights. The optimiser reads all the gradients and adjusts the parameters. One step of gradient descent. The loss should be slightly lower after this — over thousands of steps, the model learns.
model.eval() with torch.no_grad(): # Validation loop here
Evaluation mode after each epoch. model.eval() turns off Dropout and makes BatchNorm use running statistics. no_grad() disables gradient computation (faster + less memory). This is where you check performance on unseen validation data.
Complete Code training_loop.py 
import torch
import torch.nn as nn
import torch.optim as optim

def train(model, train_loader, val_loader, num_epochs=10):
    criterion = nn.CrossEntropyLoss()
    optimizer = optim.AdamW(model.parameters(), lr=3e-4)

    for epoch in range(num_epochs):
        # ----- Training -----
        model.train()
        train_loss = 0.0

        for X, y in train_loader:
            optimizer.zero_grad()
            logits = model(X)
            loss = criterion(logits, y)
            loss.backward()
            optimizer.step()
            train_loss += loss.item()

        # ----- Validation -----
        model.eval()
        correct = 0

        with torch.no_grad():
            for X, y in val_loader:
                logits = model(X)
                preds = logits.argmax(dim=-1)
                correct += (preds == y).sum().item()

        avg_loss = train_loss / len(train_loader)
        acc = correct / len(val_loader.dataset)
        print(f"Epoch {epoch+1}/{num_epochs}  loss={avg_loss:.4f}  acc={acc:.3f}")
Chapter 10

Datasets & DataLoaders

PyTorch provides a clean abstraction for feeding data: Dataset defines what your data is, and DataLoader handles how to batch, shuffle, and load it efficiently during training.

Custom Dataset

Python — Custom Dataset
class MyDataset( torch.utils.data.Dataset ):
Inherit from torch.utils.data.Dataset. To create a custom dataset you must implement exactly two methods: __len__ and __getitem__. The Dataset class itself doesn't do any loading — it just defines the interface.
def __len__(self): return len(self.data)
Return the total number of samples. The DataLoader calls this to know how many batches to create. If you have 60,000 images and batch_size=64, it will create ceil(60000/64) = 938 batches.
def __getitem__(self, idx): return self.data[idx], self.labels[idx]
Return the sample at index idx. The DataLoader calls this for each sample it needs to assemble a batch. Return a tuple of (input, label). This is where you can apply augmentations or transforms.

loader = DataLoader( dataset, batch_size=64, shuffle=True, num_workers=4 )
Wrap a dataset in a DataLoader. batch_size controls how many samples per batch. shuffle=True randomises the order each epoch (important for training; prevents the model from memorising order). num_workers=4 uses 4 subprocesses for parallel data loading — speeds up I/O-bound datasets significantly.

Iterate over batches. Each iteration yields a batch. X has your features and y has your labels, both with the batch dimension as the first axis. The DataLoader handles all the indexing, collation, and parallel loading.

Chapter 12

Convolutional Networks

A Convolutional Neural Network (CNN) is designed for grid-structured data like images. Instead of connecting every pixel to every output (expensive and ignores spatial structure), convolutional layers slide a small kernel (filter) across the image, detecting features like edges, textures, and patterns wherever they appear.

A kernel is like a stamp — you press the same stamp across the entire image, producing a map of "where this feature is". You learn many different stamps, each detecting a different feature. Early layers detect edges, later layers detect shapes, the final layers detect objects.

— Convolutions as feature detectors
Python — Convolutional Layers
nn.Conv2d( in_channels=1, out_channels=32, kernel_size=3 )
2D Convolution layer. in_channels=1 means grayscale input. out_channels=32 means we learn 32 different filters (producing 32 feature maps). kernel_size=3 means each filter is 3×3 pixels. The layer has 1×32×3×3 + 32 = 320 learnable parameters.
nn.Conv2d(1, 32, 3, padding=1)
Padding preserves spatial dimensions. Without padding, a 3×3 conv on a 28×28 image produces a 26×26 output. padding=1 adds a border of zeros, keeping the output at 28×28. Use padding='same' for the same effect automatically.
nn.MaxPool2d( kernel_size=2, stride=2 )
Max pooling halves the spatial dimensions. Takes the maximum value in each 2×2 window. This reduces computation, adds translation invariance (feature found slightly off-center is still detected), and increases the receptive field of later layers.
Complete Code simple_cnn.py 
import torch
import torch.nn as nn
import torch.nn.functional as F

class SimpleCNN(nn.Module):
    def __init__(self):
        super().__init__()
        # Feature extraction: conv layers detect local patterns
        self.conv1 = nn.Conv2d(1, 32, kernel_size=3, padding=1)
        self.conv2 = nn.Conv2d(32, 64, kernel_size=3, padding=1)
        self.pool  = nn.MaxPool2d(2, 2)   # Halves spatial dimensions

        # Classification head: linear layers on flattened features
        # After 2 pools on 28x28: 28→14→7, with 64 channels → 64*7*7=3136
        self.fc1 = nn.Linear(64 * 7 * 7, 128)
        self.fc2 = nn.Linear(128, 10)

    def forward(self, x):
        x = self.pool(F.relu(self.conv1(x)))  # [B,1,28,28]→[B,32,14,14]
        x = self.pool(F.relu(self.conv2(x)))  # [B,32,14,14]→[B,64,7,7]
        x = x.flatten(1)                     # [B, 3136]
        x = F.relu(self.fc1(x))               # [B, 128]
        x = self.fc2(x)                       # [B, 10]
        return x

model = SimpleCNN()
x = torch.randn(4, 1, 28, 28)  # Batch of 4 grayscale images
print(model(x).shape)           # [4, 10]
Chapter 13

Overfitting & Dropout

Overfitting is when a model memorises the training data instead of learning general patterns — it performs great on training data but poorly on unseen data. Regularisation techniques fight this.

Python — Dropout
self.dropout = nn.Dropout(p=0.5)
Create a Dropout layer with probability 0.5. During training, each neuron's output is randomly zeroed out with probability p. With p=0.5, half the neurons are silenced on each forward pass. This forces the network to learn redundant representations and not rely on specific neurons.
x = self.dropout(x)
Apply dropout to activations. During training, this randomly zeros ~50% of values. During evaluation (after model.eval()), dropout does nothing — all neurons are active. This asymmetry is why you must always call model.eval() before inference.
nn.Dropout(p=0.1) # Transformers nn.Dropout(p=0.5) # MLPs
Typical dropout rates. Transformers commonly use p=0.1 (10%) as they're already regularised by other means. MLPs often use 0.3–0.5. Higher = more regularisation but potentially slower learning. Tune this if your model overfits.
Train vs Eval Mode

Dropout behaves differently in training vs evaluation. Always remember: model.train() before training batches, model.eval() before validation or inference. Missing this is a common source of mysteriously bad evaluation results.

Complete Code dropout.py 
import torch
import torch.nn as nn
import torch.nn.functional as F

class RegularisedMLP(nn.Module):
    def __init__(self, dropout_rate=0.3):
        super().__init__()
        self.fc1     = nn.Linear(784, 512)
        self.fc2     = nn.Linear(512, 256)
        self.fc3     = nn.Linear(256, 10)
        self.dropout = nn.Dropout(dropout_rate)

    def forward(self, x):
        x = x.view(-1, 784)
        x = F.relu(self.fc1(x))
        x = self.dropout(x)     # Applied AFTER activation
        x = F.relu(self.fc2(x))
        x = self.dropout(x)
        x = self.fc3(x)          # No dropout on output layer

Batch Normalisation

Batch Normalisation (BatchNorm) normalises the activations within each mini-batch to have zero mean and unit variance, then applies learnable scale and shift parameters. It dramatically speeds up training and acts as mild regularisation.

Python — Batch Normalisation
nn.BatchNorm1d(num_features=256)
BatchNorm for 1D data (fully connected layers). num_features must match the number of outputs from the previous linear layer. It will normalise each feature (column) across the batch.
nn.BatchNorm2d(num_features=64)
BatchNorm for 2D data (convolutional layers). num_features is the number of channels. Normalises across spatial dimensions and the batch, so each channel has zero mean and unit variance.
# Placement pattern: linear → batchnorm → relu
BN comes after the linear operation, before the activation. This is the standard order: linear layer produces output, BatchNorm normalises it, then ReLU applies non-linearity. Note: transformers use LayerNorm instead (different normalisation scope).
Complete Code batchnorm.py 
import torch
import torch.nn as nn
import torch.nn.functional as F

class BNNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(784, 512, bias=False) # bias=False with BN
        self.bn1 = nn.BatchNorm1d(512)
        self.fc2 = nn.Linear(512, 256, bias=False)
        self.bn2 = nn.BatchNorm1d(256)
        self.fc3 = nn.Linear(256, 10)

    def forward(self, x):
        x = x.view(-1, 784)
        x = F.relu(self.bn1(self.fc1(x)))  # Linear → BN → ReLU
        x = F.relu(self.bn2(self.fc2(x)))
        x = self.fc3(x)
        return x

# saving a tiny bit of memory with identical expressivity.
Chapter 15

Word Embeddings

Text is discrete — networks work with continuous numbers. Embeddings are a learned mapping from token IDs (integers) to dense vectors. Each word or token gets a vector of floating-point numbers that encodes its meaning and relationships to other tokens.

"cat" and "dog" should have similar embedding vectors because they're both small domestic animals. "cat" and "skyscraper" should be far apart. The network learns these relationships automatically from the training data.

— What embeddings encode
Python — nn.Embedding
embedding = nn.Embedding( num_embeddings=50000, embedding_dim=512 )
Create an embedding table. num_embeddings is vocabulary size — how many unique tokens exist. embedding_dim is the size of each token's vector. Internally this is a matrix of shape [50000, 512]. Each token ID is a row index into this table.
token_ids = torch.tensor([42, 17, 5]) vecs = embedding(token_ids)
Look up embeddings by token ID. token_ids is a tensor of integers. The embedding layer does a table lookup: token 42 → row 42 of the weight matrix. vecs will have shape [3, 512] — three 512-dimensional vectors.
embedding = nn.Embedding( vocab_size, dim, padding_idx=0 )
padding_idx keeps token 0's embedding as zeros. When batching sequences of different lengths, short sequences are padded with zeros. Setting padding_idx=0 ensures the padding token always produces a zero vector that contributes nothing to the computation.

Recurrent Networks (RNNs & LSTMs)

A Recurrent Neural Network (RNN) processes sequences one step at a time, maintaining a hidden state that carries information from previous steps. This makes them suitable for sequences — but they struggle with long-range dependencies.

LSTMs (Long Short-Term Memory networks) solve this with a more sophisticated gating mechanism, allowing information to persist over hundreds of steps.

Python — LSTM
lstm = nn.LSTM( input_size=256, hidden_size=512, num_layers=2, batch_first=True )
Create an LSTM. input_size is the embedding dimension. hidden_size is the number of LSTM units. num_layers=2 stacks two LSTMs, where the output of the first feeds into the second. batch_first=True makes input shape [batch, seq, features] — much more intuitive than the default.
output, (h_n, c_n) = lstm(x)
Run the LSTM over a sequence. x has shape [batch, seq_len, input_size]. Returns: output (hidden states at every timestep, shape [batch, seq, hidden]), h_n (final hidden state), c_n (final cell state — the LSTM's long-term memory).
last = output[:, -1, :]
Take the last timestep's output for classification. For tasks like sentiment analysis, you only need the final summary of the sequence — the last hidden state. Index -1 selects the last step. Shape becomes [batch, hidden_size].
RNNs vs Transformers

RNNs and LSTMs process sequences step-by-step — they can't parallelise across a sequence. Transformers (next chapters) process the entire sequence at once with attention, making them much faster on modern hardware. Modern LLMs all use transformers. But understanding RNNs builds intuition for what transformers solve.

Complete Code lstm_classifier.py 
import torch
import torch.nn as nn

class LSTMClassifier(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_size, num_classes):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.lstm = nn.LSTM(
            input_size=embed_dim,
            hidden_size=hidden_size,
            num_layers=2,
            batch_first=True,
            dropout=0.3
        )
        self.classifier = nn.Linear(hidden_size, num_classes)

    def forward(self, token_ids):
        x = self.embedding(token_ids)       # [B, S] → [B, S, E]
        output, (h_n, _) = self.lstm(x)    # Process sequence
        last = output[:, -1, :]             # [B, H] — last timestep
        logits = self.classifier(last)      # [B, num_classes]
        return logits

model = LSTMClassifier(
    vocab_size=10000, embed_dim=128,
    hidden_size=256, num_classes=2
)
x = torch.randint(0, 10000, (8, 64))  # Batch of 8 sequences, length 64
print(model(x).shape)  # [8, 2]

The Attention Mechanism

Attention is the core innovation of modern AI. Instead of summarising a sequence into a single hidden state (like RNNs), attention lets every position in the output look at every position in the input — directly — and decide how much to "attend" to each one.

Attention(Q, K, V) = softmax( QKᵀ / √dₖ ) · V
Q = Queries, K = Keys, V = Values, dₖ = key dimension. The scale √dₖ prevents gradients from vanishing when dₖ is large.

Imagine you're reading "The cat sat because it was tired." Attention lets the network automatically figure out that "it" refers to "cat" — by computing how relevant each word in the sentence is to understanding the word "it".

— What attention solves: long-range dependencies
Python — Scaled Dot-Product Attention
Q = query(x) # [B, S, dₖ] K = key(x) # [B, S, dₖ] V = value(x) # [B, S, dᵥ]
Project input x into Queries, Keys, and Values. These are three separate linear projections of the same input. The Query asks "what am I looking for?", the Key says "what do I contain?", and the Value says "what information do I carry?".
scores = (Q @ K.transpose(-2, -1) / math.sqrt(d_k))
Compute attention scores. For each query token, dot-product with every key token — this gives a similarity score. Divide by √d_k to prevent the scores from getting so large that softmax saturates (producing near-zero gradients).
scores = scores.masked_fill( mask == 0, float('-inf') )
Apply a causal mask for language models. In an LLM, token at position i should only attend to positions ≤ i (the future is unknown). We set future positions to -∞ so they become 0 after softmax. This is the "autoregressive" property.
weights = F.softmax(scores, dim=-1)
Convert scores to attention weights. Softmax turns the scores into a probability distribution — how much attention to pay to each position. High score = look here a lot; low score = mostly ignore this.
output = weights @ V
Compute weighted sum of values. Each output position is a weighted average of all Value vectors, where the weights came from the attention scores. This is how information flows: "focus heavily on the cat when computing the embedding of 'it'".

Multi-Head Attention

Instead of one attention computation, we run several in parallel (each "head") with different learned projections. Each head can attend to different aspects of the sequence — syntax, semantics, coreference — simultaneously.

Python — nn.MultiheadAttention
mha = nn.MultiheadAttention( embed_dim=512, num_heads=8, batch_first=True )
Create multi-head attention. embed_dim=512 is the model dimension. num_heads=8 means 8 parallel attention heads, each operating on 512/8=64 dimensions. The outputs are concatenated and projected back to 512. batch_first=True for the standard [batch, seq, dim] convention.
out, weights = mha(Q, K, V, attn_mask=mask)
Run multi-head attention. Returns the attended output (same shape as Q) and the attention weight matrix (useful for visualisation). Pass a causal mask via attn_mask for language modelling tasks.
Complete Code attention.py 
import torch
import torch.nn as nn
import torch.nn.functional as F
import math

class SelfAttention(nn.Module):
    def __init__(self, embed_dim, num_heads):
        super().__init__()
        self.d_head = embed_dim // num_heads
        self.num_heads = num_heads
        # One combined linear for Q, K, V (3x for efficiency)
        self.qkv = nn.Linear(embed_dim, 3 * embed_dim)
        self.out = nn.Linear(embed_dim, embed_dim)

    def forward(self, x, causal=True):
        B, S, E = x.shape
        QKV = self.qkv(x).reshape(B, S, 3, self.num_heads, self.d_head)
        QKV = QKV.permute(2, 0, 3, 1, 4)  # [3, B, H, S, D]
        Q, K, V = QKV[0], QKV[1], QKV[2]

        scores = (Q @ K.transpose(-2, -1)) / math.sqrt(self.d_head)

        if causal:
            mask = torch.tril(torch.ones(S, S, device=x.device))
            scores = scores.masked_fill(mask[None, None] == 0, float('-inf'))

        weights = F.softmax(scores, dim=-1)
        out = weights @ V                          # [B, H, S, D]
        out = out.permute(0, 2, 1, 3).reshape(B, S, E)
        return self.out(out)

The Transformer Architecture

The Transformer was introduced in the 2017 paper "Attention Is All You Need" and is the architecture underlying virtually every modern LLM. It combines multi-head self-attention with a feed-forward network, layer normalisation, and residual connections.

ComponentPurposeKey Parameter
Token EmbeddingMaps token IDs to vectorsvocab_size × d_model
Positional EncodingInjects position informationmax_seq_len × d_model
Multi-Head AttentionAttends across the sequencenum_heads, d_model
Feed-Forward NetworkProcesses each position independentlyd_ff = 4 × d_model
Layer NormalisationStabilises trainingd_model (normalise features)
Residual ConnectionPrevents vanishing gradientsoutput = sublayer(x) + x
LM HeadProjects to vocab logitsd_model × vocab_size

The Transformer Block

Python — Transformer Block
self.attn = SelfAttention(d, h) self.ln1 = nn.LayerNorm(d) self.ff = FeedForward(d) self.ln2 = nn.LayerNorm(d)
Each transformer block has four sub-components. Self-attention to mix information between positions. Two LayerNorms to stabilise the signal. A feed-forward network to process each position's representation independently (this is where most computation happens). All with residual connections around each sub-component.
x = x + self.attn( self.ln1(x) )
Pre-LayerNorm with residual connection. The residual connection (x = x + ...) adds the block's output back to its input. This allows gradients to flow unchanged from the output all the way to early layers — crucial for training very deep networks. Pre-norm (normalise before the sublayer) is now more common than post-norm as it's more stable.
x = x + self.ff( self.ln2(x) )
Same residual pattern around the feed-forward network. The FFN expands to 4× the model dimension, applies a non-linearity (usually GELU), then contracts back. This "bottleneck expansion" gives the network capacity to store factual knowledge in its weights. Famously, researchers have found that different facts can be localised to specific FFN layers.

Positional Encoding

Attention is permutation-invariant — it doesn't care about order unless we tell it. Positional encodings inject position information by adding a position-dependent vector to each token's embedding.

Python — Learnable Positional Embedding
self.pos_emb = nn.Embedding( max_seq_len, d_model )
Learnable position embeddings. The simplest approach — give each position index (0, 1, 2, …, T-1) its own learnable embedding vector. GPT-2 and GPT-3 use this approach. It's simple and works well. The positions learn semantics like "early in sentence" vs "end of sentence".
positions = torch.arange(0, T) x = tok_emb + self.pos_emb(positions)
Add positional embeddings to token embeddings. Create position indices 0 to T-1, look them up in the position embedding table, and add element-wise to the token embeddings. Each token now encodes both what it is and where it is.
Complete Code transformer_block.py 
import torch
import torch.nn as nn
import torch.nn.functional as F

class FeedForward(nn.Module):
    def __init__(self, d_model, dropout=0.1):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(d_model, 4 * d_model),
            nn.GELU(),                         # Transformers use GELU
            nn.Dropout(dropout),
            nn.Linear(4 * d_model, d_model),
        )
    def forward(self, x):
        return self.net(x)

class TransformerBlock(nn.Module):
    def __init__(self, d_model, num_heads, dropout=0.1):
        super().__init__()
        self.ln1  = nn.LayerNorm(d_model)
        self.attn = nn.MultiheadAttention(
            d_model, num_heads,
            batch_first=True, dropout=dropout
        )
        self.ln2  = nn.LayerNorm(d_model)
        self.ff   = FeedForward(d_model, dropout)

    def forward(self, x):
        B, S, _ = x.shape
        # Causal mask: lower-triangular (each token attends to itself + past)
        mask = nn.Transformer.generate_square_subsequent_mask(
            S, device=x.device
        )
        # Self-attention sublayer with residual
        normed = self.ln1(x)
        attn_out, _ = self.attn(normed, normed, normed, attn_mask=mask,
                                  is_causal=True)
        x = x + attn_out
        # Feed-forward sublayer with residual
        x = x + self.ff(self.ln2(x))
        return x

Building a Mini Language Model

Now we assemble everything into a working GPT-style character-level language model. It predicts the next character in a sequence — tiny enough to train on a laptop, but a real LLM at heart.

GPT Architecture Overview

Token IDs → Embedding + Positional Embedding → N × Transformer Blocks → LayerNorm → Linear (LM Head) → Logits over vocabulary. Training objective: predict the next token at every position (cross-entropy loss). Generation: sample from the predicted distribution autoregressively.

Complete Code mini_gpt.py 
import torch
import torch.nn as nn
import torch.nn.functional as F

# ── CONFIG ─────────────────────────────────────────────────
VOCAB_SIZE  = 65      # Characters in Shakespeare
D_MODEL     = 128     # Model dimension
N_HEADS     = 4       # Attention heads
N_LAYERS    = 4       # Transformer blocks
MAX_SEQ     = 256     # Context window (max tokens)
DROPOUT     = 0.1

# ── BUILDING BLOCKS ────────────────────────────────────────
class FeedForward(nn.Module):
    def __init__(self, d):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(d, 4*d), nn.GELU(),
            nn.Dropout(DROPOUT),
            nn.Linear(4*d, d),
        )
    def forward(self, x): return self.net(x)

class Block(nn.Module):
    def __init__(self, d, h):
        super().__init__()
        self.ln1  = nn.LayerNorm(d)
        self.attn = nn.MultiheadAttention(d, h, batch_first=True,
                                           dropout=DROPOUT)
        self.ln2  = nn.LayerNorm(d)
        self.ff   = FeedForward(d)

    def forward(self, x):
        S = x.size(1)
        mask = nn.Transformer.generate_square_subsequent_mask(S, device=x.device)
        a, _ = self.attn(self.ln1(x), self.ln1(x), self.ln1(x),
                         attn_mask=mask, is_causal=True)
        x = x + a
        x = x + self.ff(self.ln2(x))
        return x

# ── FULL MODEL ─────────────────────────────────────────────
class MiniGPT(nn.Module):
    def __init__(self):
        super().__init__()
        self.tok_emb = nn.Embedding(VOCAB_SIZE, D_MODEL)
        self.pos_emb = nn.Embedding(MAX_SEQ, D_MODEL)
        self.blocks  = nn.Sequential(
            *[Block(D_MODEL, N_HEADS) for _ in range(N_LAYERS)]
        )
        self.ln_f    = nn.LayerNorm(D_MODEL)          # Final layer norm
        self.lm_head = nn.Linear(D_MODEL, VOCAB_SIZE,  # LM head
                                    bias=False)
        # Weight tying: share embedding and LM head weights
        self.lm_head.weight = self.tok_emb.weight

    def forward(self, idx, targets=None):
        B, T = idx.shape
        positions = torch.arange(0, T, device=idx.device)
        x = self.tok_emb(idx) + self.pos_emb(positions)
        x = self.blocks(x)
        x = self.ln_f(x)
        logits = self.lm_head(x)   # [B, T, vocab_size]

        loss = None
        if targets is not None:
            # Flatten for cross-entropy: [B*T, vocab] vs [B*T]
            loss = F.cross_entropy(
                logits.view(-1, VOCAB_SIZE),
                targets.view(-1)
            )
        return logits, loss

    # ── GENERATION ─────────────────────────────────────────
    @torch.no_grad()
    def generate(self, idx, max_new_tokens, temperature=1.0):
        for _ in range(max_new_tokens):
            # Crop to context window
            idx_cond = idx[:, -MAX_SEQ:]
            logits, _ = self(idx_cond)
            # Take logits at last position, scale by temperature
            logits = logits[:, -1, :] / temperature
            probs = F.softmax(logits, dim=-1)
            # Sample from the distribution
            next_tok = torch.multinomial(probs, num_samples=1)
            idx = torch.cat([idx, next_tok], dim=1)
        return idx

# Count parameters
model = MiniGPT()
n_params = sum(p.numel() for p in model.parameters())
print(f"MiniGPT: {n_params/1e6:.2f}M parameters")
# ~0.8M parameters — tiny but a real transformer!

Saving & Loading Models

After training, you need to save your model's learned parameters so you can use them later without retraining. PyTorch provides two approaches; the recommended one uses the state dict.

Python — Saving & Loading
torch.save(model.state_dict(), 'model.pth')
Save only the model's parameters (recommended). state_dict() returns an OrderedDict of all the learnable parameter tensors — weight matrices, biases, batch norm statistics. The .pth extension is convention. This is portable: you can load it into any architecture that matches.
model = MyModel() model.load_state_dict( torch.load('model.pth') )
Load parameters back. First recreate the model architecture (it must match the saved one exactly). Then call load_state_dict() to populate its parameters with the saved values. The model is now restored to the state it was in when you saved it.
model.load_state_dict( torch.load('model.pth', map_location='cpu') )
Load onto a specific device. If you saved on a GPU but are loading on a CPU (or a different GPU), use map_location to redirect. 'cpu' loads to CPU. 'cuda:0' loads to the first GPU.
checkpoint = { 'epoch': epoch, 'model': model.state_dict(), 'optim': optim.state_dict(), 'loss': best_loss, } torch.save(checkpoint, 'ckpt.pth')
Save a full training checkpoint. For long training runs, save the optimiser state too — this allows resuming training from the exact same point, including momentum buffers. Also save epoch and loss for bookkeeping.
Complete Code save_load.py 
import torch
import torch.nn as nn
import torch.optim as optim

model = nn.Linear(10, 5)
optimizer = optim.Adam(model.parameters())

# ── SAVE ────────────────────────────────────────────────
torch.save(model.state_dict(), 'model_weights.pth')

# Save full checkpoint (for resumable training)
torch.save({
    'epoch': 42,
    'model_state_dict': model.state_dict(),
    'optimizer_state_dict': optimizer.state_dict(),
    'loss': 0.034,
}, 'checkpoint.pth')

# ── LOAD ────────────────────────────────────────────────
# Load weights only
model2 = nn.Linear(10, 5)
model2.load_state_dict(
    torch.load('model_weights.pth', map_location='cpu')
)
model2.eval()   # Always eval() after loading for inference

# Load full checkpoint
ckpt = torch.load('checkpoint.pth')
model3 = nn.Linear(10, 5)
opt3   = optim.Adam(model3.parameters())
model3.load_state_dict(ckpt['model_state_dict'])
opt3.load_state_dict(ckpt['optimizer_state_dict'])
start_epoch = ckpt['epoch'] + 1   # Resume from next epoch
Chapter 21

GPU Training

Moving to a GPU can speed up training by 10–100× for large models. PyTorch's device system makes this almost seamless — you just move your model and data to the same device.

Python — Device Management
device = 'cuda' if torch.cuda.is_available() else 'cpu'
Detect the best available device. This one-liner makes your code portable — it uses a GPU if one is available, otherwise gracefully falls back to CPU. Always define device at the top of your script this way.
model = model.to(device)
Move all model parameters to the device. This transfers all weight matrices and biases to GPU memory. After this, all computations in the forward pass happen on the GPU. This is in-place but returns self, so the assignment is for clarity.
X, y = X.to(device), y.to(device)
Move data batches to the device. Model and data must be on the same device. Do this inside the training loop for each batch. Typically the DataLoader runs on CPU and you move each batch to GPU just before the forward pass.
device = 'mps' # Apple Silicon device = 'cuda:1' # 2nd GPU
Other devices. 'mps' uses Apple's Metal Performance Shaders on M1/M2/M3 Macs — much faster than CPU. 'cuda:1' selects the second GPU (zero-indexed) on multi-GPU machines.
with torch.cuda.amp.autocast(): logits = model(X)
Automatic Mixed Precision (AMP). Uses float16 for most operations (2× faster, 2× less VRAM) while keeping float32 where precision matters. The autocast context manager handles this automatically. Combined with GradScaler, this is the standard way to train large models efficiently on modern GPUs.
Complete Code gpu_training.py 
import torch
import torch.nn as nn
import torch.optim as optim

# ── DEVICE SETUP ───────────────────────────────────────────
if torch.cuda.is_available():
    device = torch.device('cuda')
elif torch.backends.mps.is_available():
    device = torch.device('mps')   # Apple Silicon
else:
    device = torch.device('cpu')
print(f"Using: {device}")

# ── MOVE MODEL ─────────────────────────────────────────────
model = nn.Sequential(
    nn.Linear(784, 256), nn.ReLU(),
    nn.Linear(256, 10)
).to(device)

optimizer = optim.AdamW(model.parameters(), lr=3e-4)
criterion = nn.CrossEntropyLoss()
scaler    = torch.cuda.amp.GradScaler()  # For AMP

# ── TRAINING WITH AMP ──────────────────────────────────────
def train_step(X, y):
    X, y = X.to(device), y.to(device)
    optimizer.zero_grad()

    with torch.cuda.amp.autocast():       # Use fp16 where safe
        logits = model(X)
        loss = criterion(logits, y)

    scaler.scale(loss).backward()         # Scaled backward
    scaler.step(optimizer)                 # Unscale and step
    scaler.update()                        # Update scaler
    return loss.item()

Fine-tuning Pre-trained LLMs

Training an LLM from scratch requires enormous compute. Instead, fine-tuning takes a pre-trained model (which has already learned vast world knowledge) and adapts it to a specific task with a small dataset. This is how chatbots, code assistants, and specialist models are built in practice.

Full Fine-tuning

Python — Hugging Face Full Fine-tune
from transformers import AutoModelForCausalLM, AutoTokenizer
Load Hugging Face Transformers. The transformers library wraps thousands of pre-trained models (GPT-2, LLaMA, Mistral, etc.) with a consistent API. AutoModel classes automatically select the right architecture for a given model checkpoint.
model = AutoModelForCausalLM.from_pretrained( "gpt2" )
Download and load a pre-trained model. This downloads GPT-2's weights (~500MB) from the Hugging Face Hub and loads them into a PyTorch model. All 124M parameters come pre-trained on a large text corpus — you're starting with a model that already "knows" a lot about language.
tokenizer = AutoTokenizer.from_pretrained( "gpt2" )
Load the matching tokenizer. Every LLM has a specific tokenizer — it must match the model. The tokenizer converts text to token IDs (integers the model understands) and vice versa. GPT-2 uses BPE (Byte-Pair Encoding) with a 50,257-token vocabulary.
tokens = tokenizer(text, return_tensors="pt" )
Tokenise input text. return_tensors="pt" returns PyTorch tensors. The result contains input_ids (token IDs) and attention_mask (1 for real tokens, 0 for padding). This is what you feed into the model.

Parameter-Efficient Fine-tuning (LoRA)

Fine-tuning all 7B parameters of a modern LLM is prohibitively expensive. LoRA (Low-Rank Adaptation) adds small trainable adapters alongside frozen pre-trained weights, reducing trainable parameters by 99%+ while achieving comparable results.

Python — LoRA with PEFT
from peft import LoraConfig, get_peft_model
Import PEFT — Parameter-Efficient Fine-Tuning library. This is Hugging Face's library that implements LoRA and other PEFT methods. Install with pip install peft.
config = LoraConfig( r=16, lora_alpha=32, target_modules=["q_proj", "v_proj"] )
Configure LoRA. r is the rank — smaller means fewer parameters (faster, more regularised). lora_alpha controls the learning rate scaling. target_modules specifies which layers get adapters — typically the query and value projections of attention. Only these tiny adapters are trained; the massive pre-trained weights stay frozen.
model = get_peft_model( base_model, config )
Wrap the base model with LoRA adapters. This inserts tiny trainable matrices alongside the frozen weights. Call model.print_trainable_parameters() to see how few parameters you're actually training — typically under 1% of the total.
Complete Code fine_tune_lora.py 
# pip install transformers peft datasets accelerate
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from peft import LoraConfig, get_peft_model
from trl import SFTTrainer   # Supervised fine-tuning trainer

MODEL_ID = "gpt2"   # or "mistralai/Mistral-7B-v0.1" etc.

# ── 1. Load base model and tokenizer ───────────────────────
tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
tokenizer.pad_token = tokenizer.eos_token   # GPT2 has no pad token

model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    torch_dtype=torch.float16,              # Load in fp16 to save memory
    device_map="auto"                       # Auto-place on available GPUs
)

# ── 2. Configure LoRA ──────────────────────────────────────
lora_config = LoraConfig(
    r=16,                          # Rank of the adapter matrices
    lora_alpha=32,                  # Scaling factor
    target_modules=["c_attn"],    # GPT-2 attention weights
    lora_dropout=0.1,
    bias="none",
    task_type="CAUSAL_LM"
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# e.g. "trainable params: 294,912 || all params: 124,735,488 || 0.24%"

# ── 3. Train ───────────────────────────────────────────────
training_args = TrainingArguments(
    output_dir="./ft_output",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    learning_rate=2e-4,
    fp16=True,
    logging_steps=10,
    save_strategy="epoch"
)
